# Деплой ROFL HUB на Railway (связка с GitHub)

Инструкция для владельца. После настройки каждый `git push` в `master`
автоматически перезапускает ботов на сервере — локальный компьютер больше не нужен.

> Сейчас на Railway живёт ТОЛЬКО база PostgreSQL. Ниже — как добавить туда оба бота.

---

## Шаг 0. Что уже готово в репозитории

- `Procfile` — объявляет два процесса: `main` (главный бот) и `admin` (админ-бот);
- `requirements.txt` — все зависимости с зафиксированными версиями;
- миграции схемы идемпотентны — каждый рестарт безопасно прогоняет их заново;
- подключение к базе с ретраями — если база поднимается дольше бота, он подождёт.

## Шаг 1. Подключить GitHub к Railway

1. Зайди на https://railway.app → свой проект (где уже живёт PostgreSQL).
2. **+ New → GitHub Repo** → авторизуй Railway в GitHub (однократно) →
   выбери репозиторий `kolesnikov-code/rofl-hub`, ветку `master`.
3. Railway создаст сервис из репозитория. Это будет **главный бот**.
   Переименуй сервис в `main-bot` (Settings → Service Name).

## Шаг 2. Назначить команду запуска главного бота

У сервиса `main-bot`: **Settings → Deploy → Custom Start Command**:

```
python -m bots.main_bot.bot
```

## Шаг 3. Добавить второй сервис — админ-бот

1. В том же проекте: **+ New → GitHub Repo** → тот же репозиторий `rofl-hub`.
2. Переименуй сервис в `admin-bot`.
3. Start Command:

```
python -m bots.admin_notifier_bot.bot
```

## Шаг 4. Переменные окружения

Для КАЖДОГО из двух сервисов: **Variables** → добавить (значения — из твоего локального `.env`):

| Переменная | main-bot | admin-bot | Что это |
|---|---|---|---|
| `DATABASE_URL` | ✅ | ✅ | Ссылка на PostgreSQL. В Railway: **Add Variable Reference** → выбери Postgres → `DATABASE_URL` (подставится сам) |
| `MAIN_BOT_TOKEN` | ✅ | ✅ | Токен главного бота (@BotFather). Админ-боту нужен для ЛС игрокам и возвратов Stars |
| `ADMIN_BOT_TOKEN` | — | ✅ | Токен админ-бота |
| `ADMIN_ID` | ✅ | ✅ | ID админов через запятую |
| `ADMIN_SECRET_CHANNEL_ID` | ✅ | ✅ | ID тайного канала для тревог и отчётов |
| `USERS_CHANNEL_ID` | — | ✅ | ID публичного канала для анонсов аукционов |
| `MAIN_BOT_USERNAME` | — | ✅ | Юзернейм главного бота без @ (для диплинков) |
| `SHOP_TEST_MODE` | ❌ НЕ задавать | — | На проде тест-режим магазина должен быть ВЫКЛЮЧЕН |
| `SHOP_TEST_USER_IDS` | ❌ НЕ задавать | — | — |
| `WEBAPP_URL` | ✅ (после шага 5а) | — | Публичный HTTPS-адрес Mini App — см. шаг 5а |

⚠️ Важно: `DATABASE_URL` бери через Variable Reference на сервис Postgres —
тогда внутри Railway боты ходят в базу по приватной сети.

## Шаг 5. Первый деплой и проверка

1. После сохранения переменных Railway сам соберёт и запустит оба сервиса.
2. Смотри **Deployments → View Logs**. Признаки здоровья:
   - `Пул PostgreSQL инициализирован`
   - `Схема PostgreSQL синхронизирована`
   - `Главный бот @... запущен` / `СЕКРЕТНЫЙ АДМИН-БОТ ... ЗАПУЩЕН`
3. ⚠️ Останови локально запущенных ботов! Два экземпляра одного бота
   (polling) конфликтуют: Telegram вернёт `Conflict: terminated by other getUpdates`.
4. Прогони чек-лист `BLOCK5_CHECKLIST.md` на проде с тестового аккаунта.

## Шаг 5а. Включить Mini App (🎮 кнопка в чате)

Mini App живёт внутри сервиса `main-bot` (тот же процесс, порт берётся из `PORT`).

1. У сервиса `main-bot`: **Settings → Networking → Generate Domain** —
   Railway выдаст адрес вида `https://main-bot-production-xxxx.up.railway.app`.
2. Добавь переменную `WEBAPP_URL` = этот адрес (с https://, без слэша в конце).
3. После редеплоя бот сам поставит кнопку «🎮 ROFL HUB» в меню чата,
   а команда /app начнёт выдавать кнопку запуска.
4. Проверка: открой `https://<домен>/health` в браузере — должно ответить `{"ok": true}`.
5. (Опционально) В @BotFather: Bot Settings → Menu Button / Configure Mini App —
   можно привязать тот же адрес, чтобы Mini App открывался и по прямой ссылке
   `https://t.me/<бот>/app`.

⚠️ Mini App работает только по HTTPS — локально кнопка в Telegram не откроется,
но API можно проверить браузером: `http://localhost:8080/health`.

## Шаг 6. Как это живёт дальше

- **Выкатка**: `git push origin master` → Railway пересобирает и перезапускает оба сервиса
  (миграции применятся сами, экономика ленивая — простоя начислений нет).
- **Рестарт вручную**: сервис → меню ⋮ → Restart.
- **Откат**: Deployments → предыдущий деплой → Redeploy.
- **Бэкап**: команда `/backup` в админ-боте (JSON-файл в чат) — делай минимум раз в день
  перед сном и перед каждой выкаткой. Локально: `python -m scripts.backup_db`.
- **Логи**: View Logs у каждого сервиса; все ошибки пишутся туда, бот при этом живёт.

## Если что-то пошло не так

| Симптом | Причина | Лечение |
|---|---|---|
| `Conflict: terminated by other getUpdates` | Бот запущен в двух местах | Останови локальную копию |
| `Переменная ... отсутствует` в логах | Не задана переменная окружения | Шаг 4 |
| Бот молчит, логи чистые | Неверный токен | Проверь токены у @BotFather |
| `password authentication failed` | Протух DATABASE_URL | Пересоздай Variable Reference |
